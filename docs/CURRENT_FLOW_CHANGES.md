# 当前主流程变更

- 形式化入口从保存 `not_configured` 占位结果，改为自动读取每题的LTL并调用PLCverif和CBMC。旧的两题Z3映射已从该入口移除。
- 题库JSON保留233条公式，增加 `ltl.semantics` 和 `ltl.execution`。辅助定义和观察器随题目一起导入、冻结和导出；已更新整体及逐题哈希。30题具有转换定义，开放数组及VARIANT仍缺准确模型，CBMC支持IEEE浮点模型，混合精度常量及REAL数学库调用仍需进一步适配。
- 编译错误、功能测试失败仍按原预算返修；超时和工具不支持分别记录。形式化源模型反例尚未在CODESYS复现时，状态改为 `formal_blocked` 并停止自动返修。
- 时间和请求预算统一：每题6个版本、24次实际模型请求、1800秒；形式化每版默认最多120秒，并受剩余任务时间限制。证明工具本身不调用模型。
- 默认验证20次扫描；采样周期10ms。G/F/X/U/R1在扫描结束时解释，X指下一次扫描。有限前缀末尾未完成的未来义务记为 `bounded_inconclusive`，不直接判定程序错误。
- 通过独立调用方执行观察器，候选FB中的RETURN不会跳过规约检查。观察器禁止改写候选及检查器存储，也禁止读取候选私有变量。
- 只在模型副本中补全语句分号、转换具有零默认值的整数枚举并提供R_TRIG模型；原候选不修改，转换记录写入formal.json。
- 使用英文临时目录运行工具，并将模型、脚本、完整控制台记录、逐条结果和反例复制回outputs。模型生成串行，验证引擎最多两项并行，等待与执行均计时并支持取消。
- 网页、metrics.json、SUMMARY.md、run.log和events.jsonl增加性质总数/通过数、未支持数、扫描上界、逐条状态和反例。批量实验冻结统一形式化配置。

- 默认引擎由nuXmv改为CBMC；使用PLCverif的结构化C导出，自动生成有限LTL监视器。C仅是内部验证模型，原始ST不改写，用户无需维护C程序。
- 根据CFA的32/64位类型处理浮点常量，并修正nondet_float返回类型。checked.i使用明确宽度的基础类型，不依赖GCC/MSVC系统头文件。
- 只有存在满足假设的完整扫描轨迹，且数组、指针、除零、移位、整数溢出与循环展开检查全部通过时，才允许记录性质通过。矛盾约束、展开不足不会成为通过结论。
- 网页增加实际引擎、内部循环展开上限及展开检查状态；配置、指标与详细日志同步保存。

以上是流程接入和适配实现，不表示全部32题已通过验证，也不表示已完成CODESYS所有数据类型和库的准确建模。

## 实验配置界面

- 模型与环境中可分别填写并保存A/B模型名称，两者共用DMXAPI Key；B的初始建议值为qwen3.8-flash，不是固定模型。
- 模型名称以config.json为唯一来源，实验页显示已保存的A/B模型，浏览器缓存不再覆盖名称；推理模式、预算和高级参数按模型保存在当前浏览器，刷新后恢复。
- 题库范围显示实际题数，相同范围合并；恢复上次工作区导入列表与选择，避免刷新后变成0题。
- 配置检查共用批量启动的请求校验，检查当前模型参数、题目、任务并发与本地环境，不发送模型请求；界面明确区分配置检查、API连通性测试与真实编译。
- 将并发数改名为同时运行任务数，并显示总任务数和实际同时运行上限。

## 输出与停止

每次运行改用北京时间目录。批量按tasks/题号/框架_模型分组，每题外层仅保留摘要、最终ST和文本日志，机器记录收进details。整轮增加可用Excel打开的results.csv，直接列失败原因。相同题库、作者响应和已提交源码不再重复保存多份；CODESYS编译和仿真证据随源码版本保存。

新增任务边界暂停和继续：暂停等待当前任务完成，继续不重跑已完成任务；结束实验才取消未完成任务。空闲时可从网页关闭服务；Ctrl+C请求取消并等待保存。历史从磁盘恢复，正常关闭不删除记录。
