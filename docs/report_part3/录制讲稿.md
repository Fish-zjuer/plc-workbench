# 第 3 部分录制讲稿

**建议 75–85 秒。** 在组内总 PPT 中放在「测试与 LTL」之后、「结果展示」之前。把两张幻灯片复制到总稿，可选择「保留源格式」。

**第 1 页 · Agent 架构与修复闭环（约 40 秒）**

PLC 程序每次扫描都会更新状态，所以能编译的代码也可能在后续扫描出错。我们的 self Agent 和 Codex CLI 基线用不同方式写代码，但把候选代码交给同一个 Trial 控制器。它先检查接口，再走 CODESYS 或 TIA 的真实编译和仿真，最后对通过行为测试的候选运行有界形式化验证。编译错误或可复现的行为失败会带着诊断进入下一版。环境故障和待复核的反例会单独留档。两套框架每题都受六个源码版本、二十四次模型请求和三十分钟的限制。

**第 2 页 · 展示指标与证据（约 35 秒）**

结果先看首次和最终编译通过率，再看通过了多少测试场景、多少完整题目。通过率用全组计划的题数或场景数作分母，同时标出未执行的数量。形式化部分把界内通过、反例、超时和未执行分开，并标注扫描上界。以 TIA 实验中的 CUSTOM_09 为例，同一个 DeepSeek 模型，self 请求一次，Codex 请求四次，两者都通过二十五个场景和十条界内性质。每版源码和诊断都有对应的文件。接下来由结果部分展示两平台各自的实验数据。

录制前打开 CUSTOM_09 目录，预先定位 self_A 和 codex_A 的 SUMMARY.md、final.scl 和 details/receipt.json。同一个 deepseek-v4.1-flash-1017 模型下，两者都通过 25 个场景，扫描上界 20 内 10 条性质通过。self 用时 322.487 秒，Codex 用时 387.997 秒，这些时间包含并发实验中的厂商队列等待。[CUSTOM_09 实验记录](https://github.com/Fish-zjuer/plc-workbench/tree/0eaa0e571043ef8c127945613d483437a37b7b4d/outputs/tia_32x4_20261108_results/tasks/09_CUSTOM_09)
