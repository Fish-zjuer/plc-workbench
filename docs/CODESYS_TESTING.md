# CODESYS 编译与功能测试

工作台与 self/Codex 批量实验默认执行同一条检查链：候选接口检查 → CODESYS 编译 → CODESYS 仿真功能测试 → 原有形式化接口（按当前配置执行）。每次返修重新检查。取消 CODESYS 选项才会使用明确标记的本地备用流程；CODESYS 失败时不会自动回退。

## 执行方式

`plc_agent/codesys_tests.py` 将题库的输入序列编成 PLC_PRG 测试程序。每个场景使用独立功能块实例，IN_OUT 使用真实调用方存储，保留开放数组的独立下界。每行输入只调用候选功能块一次，再保存实际输出。输出读取与判据比较沿用冻结题库的预期值、容差、不变量和响应窗口。

`codesys_worker.py` 在模板工程副本中导入候选代码与测试程序，启用并读回仿真模式后才登录；不会连接物理 PLC。编译镜像、请求、响应、输出、实际执行时间与日志保存在独立证据目录。

定时用例通过 CODESYS 原生 TON 时钟等待各行 `time_ms`。这不是本地后端的可任意跳转虚拟时钟，执行需要真实时间，受仿真任务周期影响。输出中的 `actual_scan_times_ms` 记录实际采样时间；涉及原生定时器的候选，如果实际采样与指定时间偏差超过 1ms，会标为 `behavior_not_supported`，保留原始输出，不将调度误差交给模型当作逻辑错误返修。不能据此直接宣称目标 PLC 的实时性能。长时间场景、超出配置超时的测试会明确标记 `behavior_not_supported`，不会使用本地执行冒充。

## 当前限制

- `PUBLIC_04` 包含超过一小时的单场景时间跨度，当前原生时钟适配不执行该场景。
- `PUBLIC_06` 的完整时间序列超出默认 120 秒总调用超时，当前配置下会报告未支持，需要分段或另行设计经验证的时间测试。
- `PUBLIC_18` 的现有测试使用本地 PV1 VARIANT 描述符，尚无等价的原生 CODESYS 适配，报告未支持。厂商编译自身失败时仍先报告真实编译诊断。
- 形式化后端由独立模块管理，本次改动不扩大或重写其规约与能力。当前运行是否执行形式化验证，以独立形式化状态为准。

无测试用例时只报告编译通过，不报告功能测试通过。CODESYS 编译通过与功能测试状态独立统计。运行前检查在 CODESYS 模式下不再要求安装 STruC++、R4 或 g++。

## 删除本地备用方案

提交前可整体删除 `optional_local_tests/`。保留 CODESYS 选项勾选即可。备用目录缺失不会影响主流程，取消勾选时会得到明确错误。详细说明见该目录 README。
