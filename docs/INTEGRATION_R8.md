## 怎么运行这些题

仍从 launch.cmd 进入原 TUI。文件上传和计划模式照常使用。题包已规范化进 `datasets/standalone32/`，manifest 校验每题完整内容，原测试保持不变；原 ZIP SHA256 见 source_archives.json。

TUI 命令：

```text
/dataset list
/dataset show CUSTOM_01
/dataset run CUSTOM_01
```

计划模式中 run 只说明计划。切换 `/act` 后才允许模型请求、写 ST、编译与执行。自然语言工具为 `plc_dataset_list/show/run`，没有修改已冻结题面、接口或预期答案的工具。作者请求只有题面、接口、规约定义、当前代码和真实失败；初始请求不附预期答案表。

终端：

```powershell
python -m plc_agent dataset list
python -m plc_agent dataset show --ids CUSTOM_01
# 不加 --mode execute 时仅列计划
python -m plc_agent dataset run --ids CUSTOM_01 --mode execute
python -m plc_agent dataset run --ids CUSTOM_01,CUSTOM_02 --mode execute --workers 2
# 重放本版保存的全部32份真实模型候选，不发模型请求
python -m scripts.recheck_dataset
```

作者和审查仍通过自己填写的 base_url、api_key、model 接入。最多三次代码提案；编译/环境异常分层保存，不通过测试就不签发通过。独立审查看不到原预期表；新建议在实际 ST 上重放两遍。审查建议不能自动成为原题真值，矛盾或题意空缺单独保留。

## 32题桥接与边界

- 普通标量、固定数组、STRING、TIME/LTIME 按声明类型传输。自建电梯的数组保留 `[1..6]`，没有改成六个独立接口；同时检查输入数组未被程序修改。
- 公共07/17复用显式 copy-in/copy-out 结构数组驱动；不声称验证引用别名、并发或多个调用者。
- 公共08/18复用真实调用方存储驱动。FIFO检查出队值、计数、状态和空闲缓冲保持；VARIANT 仍是本地 PV ABI。
- `response_windows` 要求同一次扫描的所有目标输出一起满足，不能把不同扫描拼起来，也不要求窗口每一扫描都满足。
- 数值容差按声明类型和题包约定；整数、布尔及状态码精确比较。第04题的大时间戳使用专用桥，不强行塞进旧通用合约的时间上限。

题包自己说明的公共04首拍 CycleTime=0、公共12定时器较强关闭契约等差异记录在 SOURCE_NOTES.md。通过这些实例不是所有题面解释均已满足，也不是独立生成准确率。
