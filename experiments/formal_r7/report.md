## 新生成的弱模型程序

| 任务 | 生成修订 | 实际模型请求 | 原生基线扫描 | Z3 归纳证明 | 目标编译 |
|---|---:|---:|---:|---|---|

互锁的五条性质分别检查停止优先、互锁断开关闭、合法运行保持、按钮持续按住不自启、合法新上升沿启动。归纳证明在严格 ST 状态转移模型及报告假设下覆盖任意后续扫描；不能据此断言全部自然语言需求或硬件正确。

真实请求和完整候选在 real_model/；最终可迁移实现重新检查见 final_recheck/。后者复用历史审查模型提出的轨迹，重新编译、求解并双次重放，未请求新审查模型，也未生成新代码。

## 人工注入的延迟故障

在上面真实弱模型生成的互锁程序中，人工加入计数器：第 24 次 FB 调用后强制 running=TRUE。故障是人为构造，不能算作弱模型自然错误。

1. 原有两条基线场景共 15 次扫描，全部通过。
2. Z3 从声明初态搜索，在第 24 次扫描（零基索引 23）得到违反停止、互锁或禁止自启规则的输入序列。
3. 三条反例在同版本原生编译产物中重放两次，逐行输出与符号结果一致，确实违反相同已确认性质。
4. 程序将三个反例写入受保护的回归集，再调用 DeepSeek 修复。
5. 一次修订后，基线和回归场景共 87 次扫描、99 次断言通过；五条性质全部获得归纳证明，独立审查完成。

本次新增两次真实模型请求（修复、审查各一）。原始坏程序、反例、重放和修复后代码均在 fault_injection/，未覆盖失败证据。

## 验证范围和检查

全套回归首次运行 183 项，182 通过、1 项既有后端指纹检查跳过。随后新增的 CODESYS worker/重放比较检查，以及最终形式化、命令和小终端面板检查分别通过；当前共 188 个测试用例。CODESYS 相关测试使用明确标注的 API/进程替身，只验证导入、协议、仿真开关、错误阻断、输出顺序、双次比较和清理逻辑。

Z3 测试还核对：归纳 SAT 不能冒充可达反例；整数回绕与原生执行一致；拒绝未知后缀、计时器、外部调用与有歧义的类型提升；上一次输入/输出；语法预算；证明文件删改后结果失效；计划模式不能执行；所需证明未完成时不能通过。

可离线重算公开 SMT 查询：

```powershell
python -m scripts.verify_formal_evidence
python -m unittest discover -s tests -v
```

verify_formal_evidence 校验每个查询哈希并重新调用 Z3，不发模型请求。报告包含 SMT 文件、求解器/前端指纹、ST 和约定 SHA256。历史实测指纹可能与后续开发版不同；导入新电脑时应重新运行，不把历史记录当作新执行。

## CODESYS 还缺什么

本机 doctor 返回 setup_required、installed_candidates=[]、vendor_compile_executed=false。官方商店未登录，未下载或安装 IDE。已提供 configure/probe、单独编译、完整任务 executor=codesys、专用工程副本、真实编译映像/日志哈希和仿真行读取。官方安装、准确 profile 和可运行的仿真模板就绪后，仍需实际检验版本 API、监视读取和设备模板；当前不能声称厂商链路已经跑通。

当前 CODESYS 仿真适配限制为无时钟 BOOL/整数子集。计时器、浮点、数组、引用等不能借这个适配器算作已验证。外部 R5 可在同一后端接口上继续合并。

使用和语义范围见 [接入说明](../../docs/CODESYS_FORMAL.md)。旧 R4 的 20 题有限测试成绩保持为历史结果；本轮没有把它们改写成形式化通过率。
