# R3：上下文记忆与运行可靠性

已将压缩改为模型工作记忆、按预算保留近期原文、原始记录检索及精确版本引用。真实DeepSeek追问检查在本轮最后一次试验中11项通过；此前两次失败记录均保留。原20份ST候选没有生成或修改，16题仍通过有限检查。

旧版实际已有模型摘要，但近期原文固定为两轮，摘要请求本身没有单独预算，也不能处理单轮不断增长的工具记录。这些限制已经处理。下面列出本轮查到的具体问题与验证，不能据此声称所有可能的错误都已消失。

## 真实模型记忆试验

输入是一段构造的长对话，包含项目要求、旧结论、更正、失败和版本变化。摘要后另行询问，不把期望答案提供给模型。

| 试验 | 结果 | 逻辑模型调用 |
|---|---|---|
| [主任务思考设置直接用于2048摘要预算](live_recall_thinking_length_failure.json) | length截断；原文未替换 | 1 |
| [摘要独立关闭思考，尚无精确引用表](live_recall_before_reference_ledger.json) | 压缩成功，追问10/11；完整SHA回答为null | 2 |
| [加入精确引用表](live_recall.json) | 压缩及11/11追问通过 | 2 |

追问覆盖：服务无关配置、TUI、上传要求、冷却从2秒更正为3秒、停止优先、源码路径、完整最新SHA、行为尚未验证、CODESYS未运行、没有形式化证明，以及初始化尚未修复的缺陷。

模型摘要负责目标、约束、决策和工作进展。精确引用表只保留标识、原始片段和来源，不自动把用户或模型的陈述当成已验证事实。实际源码验证仍由哈希绑定的执行记录判断。

这只是同一组构造历史的迭代试验，最后一个成功样本不能用来估计普遍可靠率。原始输入见[fixture.json](fixture.json)，失败结果没有删除。本轮余额观测减少约¥0.03，可能存在结算延迟，不能当作逐请求账单。

## 回归与后端边界

完整工具回归 **117项通过**，见[regression_tests.log](regression_tests.log)与[最终核验](final_validation.json)。包括真实ST编译/行为测试、本地HTTP/SSE、Textual界面、压缩和恢复检查；模拟服务的检查不算模型质量。CLI历史检索也已实际执行，能分页取回原话。

[20题重新检查](bank_replay.json)完全复用R2最终ST，每份源码哈希不变，模型生成调用为零。16题通过当前有限检查，04/12仍缺少LTIME支持，08仍受开放数组构造和绑定限制，18仍缺少VARIANT后端。原始固定判据哈希未变。

第18题还存在明确的旧候选实现缺失：正文没有读写item或buffer，容量保持0，不能实现题意所要求的元素存取。旧报告只把它归入后端阻塞是不充分的。现在执行记录另列candidate_warnings和incomplete，不再把补齐编译器视为唯一剩余工作；本轮没有代替模型修改ST或把它计为通过。

VARIANT的目标平台语义仍须明确：[Siemens官方文档](https://docs.tia.siemens.cloud/r/en-us/v20/data-types/pointer/variant-s7-1200-s7-1500/variant-instructions-s7-1200-s7-1500?contentId=GksN6rVKjr8dis59wfdBHQ)列出了该类型的计数及复制指令；[CODESYS文档](https://content.helpme-codesys.com/en/CODESYS%20Development%20System/_cds_datatype_any.html)描述的是ANY泛型接口。由此只能判断不能未经映射就混用两套接口，不能凭空宣布题面必属某一厂商。

本机仍未执行CODESYS、形式化求解器或实体PLC。本轮解决的是已定位的agent实现问题和结果漏报；尚未补齐这4题的执行能力，也没有完成第18题的可验证实现。

## 使用

```text
/compact
/memory
/history 停止优先
/pin 停止必须优先于启动
/pins
/unpin 1
```

模型配置页可设置近期原文轮数、压缩目标比例、摘要输出预算和仅压缩使用的服务扩展参数。默认不预设厂商；本机DeepSeek摘要参数是`{"thinking":{"type":"disabled"}}`。

```powershell
python -B -m plc_agent compact
python -B -m plc_agent memory
python -B -m plc_agent history '停止优先' --max-events 8
```
