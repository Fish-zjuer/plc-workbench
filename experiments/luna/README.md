# GPT-6 Luna：独立生成及工具反馈实测

状态：本轮完成，待审核。

用户要求用较弱模型生成待测内容，避免由工具作者同时写出所有被测程序。已通过子代理选择 `gpt-6-luna`，主代理负责工具、执行与记录；首稿及全部 ST 修订均由 Luna 编写。

## 生成与评估约定

- 首稿只提供原始题面及功能块命名要求，明确要求不读取参考实现、人工故障目录、测试或监视器，不运行编译测试。
- 先测三道简单题，全部通过后，追加两道中等公共题。最初三题的独立结果保留在 `results/initial_three/`。
- 每轮使用同一行为监视器及场景生成代码，固定随机种子 20261027。JSON 中记录代码哈希。
- 编译及执行后端为 **STruC++ 0.7.0 + g++**；没有运行 CODESYS 编译、PLCVerif 或实体 PLC。
- 编译失败、执行错误、性质违反、测试通过分开记录；没有把不可执行程序计为行为测试失败。
- 反馈由主代理把实际工具结果交给 Luna；主代理没有改写 Luna 的 ST。此实验不是已经自主运行的完整模型 API agent。

## 实际结果

| 任务 | 首稿 | 第一次反馈修订 | 第二次反馈修订 |
|---|---|---|---|
| 电机启停（文档示例） | 当前测试通过 | 首稿原样复制，通过 | 首稿原样复制，通过 |
| 风机延时启动（公共题 06） | 当前测试通过 | 首稿原样复制，通过 | 首稿原样复制，通过 |
| DWORD 边沿检测（公共题 02） | 当前测试通过 | 首稿原样复制，通过 | 首稿原样复制，通过 |
| 移动平均（公共题 09） | 当前测试通过 | 首稿原样复制，通过 | 首稿原样复制，通过 |
| IPv4 解析（公共题 14） | ST 前端通过，生成的 C++ 编译失败；未测行为 | ST 前端通过，另一处 C++ 兼容失败；未测行为 | 编译执行及当前测试通过 |

IPv4 首稿使用字符串下标，离线编译器生成 `IECStringVar<254>.at(...)`，而其运行时没有这个成员。第一次修订改用 MID，但字符串与字面量的 `<` / `>` 比较又触发缺少 C++ 运算符重载的问题。第二次修订避开这两类操作，才进入行为测试。

**这里发现的是离线后端兼容问题，尚无依据把它判成 CODESYS 代码错误或模型逻辑能力不足。** 对原本可执行的四道题，本轮没有找到违反当前契约的行为，不需要伪造一个修复案例。

## 这轮支持什么结论

1. 工具反馈确实能指导 Luna 改写为当前后端可执行的程序，完整过程及两个失败版本可重现。
2. 检查工具必须区分“程序行为错误”和“验证/执行后端不支持”，否则编译器缺陷可能被误算成模型失败。
3. 当前五题不足以证明复杂修复策略的收益，也不能估计 Luna 的总体正确率。
4. 下一步应在 CODESYS 对原始和修订版本交叉检查，并加入未按当前场景设计编写的更复杂实现。现有结果不能代替作业的四组实验。

## 留档
